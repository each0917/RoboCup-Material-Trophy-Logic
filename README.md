# RoboCup 搬运小车：算力受限下的超时容错与多级推理调度

> **作者**：2026 开飞机的娃子 (1211959902@qq.com)
> **协议**：MIT License

本仓库开源了 RoboCup 竞技搬运小车 **高层任务处理核心逻辑（`grab1`/`put1`/`newgrab1`/`newput1`）**。在不升级底层硬件、不增加视觉模型复杂度的前提下，纯通过轻量级状态机与统计逻辑，应对赛场上视觉断流、算力瓶颈与目标误判。

---

## 📌 背景痛点与极限算力剖析

赛场上常规“强依赖逐帧视觉输出”的方案极易死锁。本系统的软硬件运行在极度紧绷的算力边缘：

### 📊 主控端 (STM32F429ZGT6) 数据指标
- **核心算力**：Cortex-M4 @ 180MHz，带单精度 FPU，**无 NPU/AI 硬件加速**。
- **时序死线 (Deadline)**：需要维持 **5ms ~ 10ms** 的底盘麦克纳姆轮闭环控制（PID解算 + 运动学逆解）。
- **通信负载**：多路串口并发（视觉、IMU、上位机、电机）。若视觉以 921600 波特率高频上传多目标坐标包，串口中断将严重挤占控制周期，**导致底盘响应延迟甚至失控**。
- **本模块开销**：纯逻辑推演、数组遍历与计数，无浮点重计算，**耗时在微秒级**，绝不抢占控制时间片。

### 📊 视觉端 (MaixCAM Pro) 数据指标
- **并发任务**：单帧内需同时执行多类别目标检测（红/蓝圆柱、方块、黄锥、圆环）+ 汉字 OCR（冠/亚/季）。
- **掉帧与假死**：满负荷下实测有效输出帧率从 30fps 跌至 **10fps 以下**；通信延迟常出现 **100ms ~ 300ms 的断流**。
- **误判率跳变**：反光与遮挡导致汉字 OCR 置信度在 0.3 ~ 0.9 剧烈震荡，单帧识别极易张冠李戴。

## ✨ 核心设计策略 (纯软件层兜底)

### 1. 视觉断流下的物料颜色推理
**痛点**：识别超时或丢包时，传统代码死等新帧导致卡死。
**策略**：利用赛题**“每轮固定 2红 2蓝”**的数学约束，基于已入库数量反推当前颜色（`infer_color`）。形状降级为未知（`SHAPE_UNKNOWN`）。保障 300ms 丢包或 10s 断流时，“无视觉也能抓”。

### 2. 第5个物料（黄锥）的免视觉开销独立通道
**痛点**：每次视觉校准与识别都会占用宝贵的主控时间与视觉算力。
**策略**：在 `grab1(5)` 函数入口直接拦截，**完全跳过校准和视觉采样**，走纯开环的机械臂动作。该动作独立于红蓝物料的数组管理，不占用位置计数，将算力彻底让给前 4 个物料。

### 3. 放置端优先级调度
**痛点**：时间窗有限，复杂物料对位耗时过长。
**策略**：`put1` 执行严格的物料优先检索机制：**圆柱优先 > 方块次之 > 未知最后**。利用圆柱物理容错率高的特性，优先完成搬运以释放算力与时间片。

### 4. 奖杯多轮采样与全局枚举消抖
**痛点**：汉字 OCR 置信度频繁跳变。
**策略**：单杯进行最多 5 轮（每轮25次）的采样计数；利用“名次互斥”约束，计算 3! = 6 种冠亚季排列的全局置信度（`global_assign`）。若全局失效，启动排除法保底（`fallback_assign`）。

## 🚀 移植与对接说明

本模块（`robocup_task_logic.c` / `.h`）高度解耦，去除了底层驱动。使用者需自行对接以下 `extern` 接口：

- `Car_Adjust_All()`：底盘闭环校准接口。
- `SetMaixCamMode()` 与 `WuLiaoData`：视觉模式切换与数据接收。
- `HuaTai_X/Z()`、`move_distance_namara_car()`：机械臂与底盘运动驱动。

接入后，任务层按以下逻辑调度：

```c
/* === 阶段 1：红蓝物料抓放 === */
grab1(1); grab1(2); grab1(3); grab1(4); // 视觉引导，带超时推理
put1(1); put1(2);                       // 按圆柱优先放置

/* === 阶段 2：黄色物料独立抓取 === */
grab1(5); // 纯开环动作，跳过视觉与数组，独立抓取

/* === 阶段 3：奖杯抓放 === */
newgrab1(0); newgrab1(1); newgrab1(2);  // 多角度采样投票
newput1(0); newput1(1); newput1(2);     // 按冠亚季名次放置
